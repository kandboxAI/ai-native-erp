# 企业管理底座设计（当前实现入口）

本文描述底座的通用能力。行业功能见[所属插件文档](README.md#插件领域设计)。

## 1. 底座范围

实际后端模块由 plugins/core/backend/app/framework/core_manifest.json 限定。认证在 app/auth，配置和会话在 core/framework，通用管理在 modules。管理端及小程序保留登录、导航、用户授权、通用消息/待办等外壳；业务页面随插件装配。

| 能力 | 当前职责 |
| --- | --- |
| 认证与租户 | public 登录账号、租户及成员关系；JWT 会话与 Redis refresh token；请求建立已验证租户上下文 |
| 用户和授权 | 租户用户、组织/部门/岗位、角色、权限、数据范围；不按行业角色名放行 |
| 目录与配置 | 菜单、小程序菜单、字典、系统参数；插件以声明注册，不修改底座硬编码入口 |
| 工作流与通知 | 通用流程、任务、消息与场景机制；业务注册模板及处理器 |
| 文件与附件 | 通用文件上传、绑定及访问治理；业务注册场景和访问检查，不自行维护另一套文件库 |
| 集成和审计 | 事件出站、操作与登录记录；后台工作显式绑定租户 |
| AI 基础设施 | 模型网关、受控接口/表查询、资源检索及敏感结果保护；行业资源由插件提供 |

## 2. 注册与运行

插件源码、部署装配、租户启停与用户权限是四个阶段。插件通过清单和现有收集器登记模型、API、catalog、dictionary_specs、tenant_setup、AI 提供器等。加载不代表该租户已开通；客户端显示入口也不代替服务端鉴权。

具体契约见 [插件架构](current-plugin-architecture.md) 和 [当前架构边界](core-architecture.md)，不假定不存在的热安装或远程插件商店能力。

### 角色菜单编辑的目录范围

角色菜单绑定列表、管理端菜单树和批量保存校验共用当前部署及已验证租户启用插件的可授权目录；绑定查询在统计、分页前过滤退役入口、其被屏蔽下级及未启用插件入口。前端保存只提交当前完整菜单树内的勾选，隐藏路由仍属该目录，不受搜索或当前展开状态影响。历史绑定中不可编辑的菜单不随本次保存撤销，也不因新勾选入口恢复显示。服务端继续拒绝目录外 ID，目录变动时要求刷新重试；内置管理员已有当前目录菜单不能减少。菜单与接口权限分别保存，不通过菜单操作补授接口权限。

左侧菜单及角色菜单编辑共用前端分组投影。优先按已授权锚点选择分组；没有顶层锚点时，按分组中已授权的具体入口匹配，避免仅有审批、文档或物资入口的账号回到原始目录布局。投影只重排已有授权入口，不补授菜单或接口权限；没有匹配入口时保留原导航。

## 4. 规划和历史

旧知识库、文档中心、AI 控制中心等设计中存在尚未落地的规划。不能因预留了 kb_、doc_ 或 ai_ 前缀就声称功能已实现。原文件可从本地历史归档阅读；后续实施时先核对当前模型、注册点及测试。
