# 目录命名规范

适用于底座、业务插件、管理端、小程序以及开发工具。代码评审和 AI 开发均按本规范检查。

## 新增目录

- 使用英文单数名词或表达职责的词组；即使目录存放多份文件、多个对象，也使用单数。
- 复合名称中的实体词同样使用单数，例如 `work_order`，不使用 `work_orders`。
- 延续所属技术栈的大小写与分隔符约定；本规则约束单复数，不统一改写现有命名风格。
- 按词义判断单复数，不按末尾是否为 `s` 判断。`status`、`analysis` 是单数，`mes` 是业务缩写，均可使用。

| 用途 | 新增目录使用 | 不使用 |
| --- | --- | --- |
| 文档 | `doc` | `docs` |
| 脚本 | `script` | `scripts` |
| 测试 | `test` | `tests` |
| 插件、模块 | `plugin`、`module` | `plugins`、`modules` |
| 组件、页面 | `component`、`view` | `components`、`views` |
| 服务、资源 | `service`、`asset` | `services`、`assets` |
| 工具 | `utility` 或 `util` | `utils` |

## 已有目录与固定契约

- 现有 `docs/`、`scripts/`、`tests/` 等目录保留；向已有目录增加文件时继续使用原路径，不新建一套单数目录与其并存。新增普通子目录遵守单数规则。
- 当前插件源码布局等已发布路径契约继续有效，例如 `plugins/<key>/backend/app/modules/`、`web/src/views/`。不得仅为统一命名而修改导入路径、路由、打包清单或脚手架固定布局。
- 第三方依赖、工具强制或自动生成的目录使用其规定名称，例如 `node_modules/`、`.github/workflows/`。新增此类例外时，在对应工具或模块说明中记录名称及强制原因，不能仅以习惯为由使用复数。
- 历史目录改名属于独立重构任务，须同步引用、构建、测试发现与发布契约；本规范不要求批量改名。
