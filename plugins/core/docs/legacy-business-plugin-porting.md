# 将已有业务迁入插件

先从可访问的业务源码中确定模块、页面、迁移、权限及插件依赖。按[脚本转换](plugin-script-conversion.md)在隔离目录生成候选源码，再按[插件接入手册](business-plugin-integration.md)核对下列事项。

1. 仅收集业务模块拥有的源码和必要资源。认证、租户、工作流和文件复用底座能力，跨插件访问使用所属模块的公开 Service。
2. 在 `plugin.toml` 中登记模块、依赖与迁移分支，在 `frontend.json` 中登记页面归属。菜单、权限和字典使用所属模块的声明入口。
3. 为全新部署建立依赖 core 的初始迁移。已有数据库根据原模型与数据验证转换方案，保留已发布迁移链并审核目标环境差异。
4. 使用[源码检查与打包](plugin-development.md)验证插件，在隔离测试库验证启用、升级、数据范围和主要业务流程。
5. 使用 Harness 时，在数据库升级后按[同步说明](harness-sync.md)更新表、接口和索引。
