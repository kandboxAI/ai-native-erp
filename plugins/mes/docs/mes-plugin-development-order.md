# MES 插件化开发顺序

> 当前目标：先让能力包能按部署组合加载、按租户启停，再扩展 MES 业务。业务规则见 [MES 设计](mes-design.md)，插件契约见 [能力包架构设计](../../core/docs/foundation-platform/current-plugin-architecture.md)。本文件只规定开发先后顺序。

## 开发顺序

| 顺序 | 做什么 | 完成标志 |
| --- | --- | --- |
| 1. 定插件契约 | 以现有 `app/modules/mes` 和库存模块为试点，确定清单、依赖、模型、路由、目录、初始化与迁移的注册方式。区分部署组合加载和租户启用。 | 新能力包可以声明自己的入口；框架不写 MES 业务规则。 |
| 2. 做最小加载器 | 用清单装配现有模块，验证 `edu`、`mes`、`edu_mes`；MES 暂留在 `app/modules/mes`，不先搬目录。 | 组合外模块不被导入或注册；缺依赖、循环依赖能被发现；已有 MES 接口仍可调用。 |
| 3. 做租户启停 | 完成能力包开通状态、按需迁移与幂等初始化；请求、菜单、权限、后台任务和 AI 入口按租户状态过滤。 | 在隔离测试租户验证：一个租户启停 MES 不影响另一个租户；未开通、开通失败或已停用时，MES 接口和菜单不可用。 |
| 4. 做前端装配与组合验收 | 管理端、小程序按同一部署清单构建；核对服务端菜单、页面路径、接口权限和三种组合的产物。 | 学校组合没有 MES 页面，工厂组合没有教育页面；`edu_mes` 两者可用。 |
| 5. 修正 MES P0.1 | 修复现有工单、工序、派工、暂停／恢复、报工、冲销的状态与数量规则，补幂等、权限和组织范围测试。 | 管理端与小程序通过真实接口跑通生产执行；通过 [MES 设计](mes-design.md) §20 的 P0.1 验收后，才对生产租户开放或搬迁 MES 目录。 |
| 6. 扩展 MES 业务 | 依次实现 P0.2 产品与工艺、P0.3 库存联动、P0.4 质量与追溯。 | 每期按 MES 设计单独验收；MES 通过库存公开 Service 协作，不直接写 `inv_*` 表。 |

第 4 步的构建装配已接入仓库根目录 `deployment.json`。管理端与小程序从同一组合选择页面；在仓库根目录运行 `node scripts/verify-frontend-combinations.mjs --build` 可逐一构建并检查三种组合。校验脚本使用临时部署清单，不修改本地选择。日常开发分别在 `web/` 运行 `pnpm dev`、在 `miniprogram/` 运行 `pnpm dev:mp-weixin`，修改部署清单后重启开发服务。

**两人并行时**：一人负责加载器、租户启停和迁移装配；另一人负责现有 MES 的清单适配、管理端／小程序装配及组合测试。最小加载器可用后，第二人开始修正 P0.1。双方先约定注册接口和库存依赖，再改共享入口。

插件装配阶段复用现有 MES 作为验证样例，不以现有业务行为正确作为插件验收结果。数据库迁移的生成与执行、目标库确认仍按仓库 [AGENTS.md](../../../AGENTS.md) §10 办理。
