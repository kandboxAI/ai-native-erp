# MES 加工询价与报价

运行配置模板随包位于 `plugins/mes/config/.env.example`，实际值放在宿主 `plugins/core/backend/config/plugin/mes.env`。原 `plugins/core/backend/.env` 继续兼容，独立文件同名项优先。`MES_CNC_MAX_CONCURRENT_JOBS` 每个后端进程默认 1，可设为 1～16。修改后需重启后端，启动日志会列出 `mes.cnc.analysis` 等核价通道。安装升级保留宿主配置，模型及 OCR 密钥只填写在目标环境。详情见[插件运行配置](../../core/docs/plugin-configuration.md)。

入口为 **生产管理 → 加工询价**（`/mes/quoting`），支持 `?part_id=<UUID>` 定位零件。

## 业务范围

用户主流程为“上传并生成报价 → 修改完善 → 更新报价 → 审核与导出”；解析、规则补齐和首次核价在后台衔接：

- 一份 PDF 和/或一份 STEP/STP，单份 20 MB；PDF 最多 20 页，STEP 接受一个有效实体。
- PDF 原文、页面/局部视图、OCR 版面与 Markdown；STEP 净尺寸、体积、表面积、三维网格和几何面候选。
- 通过配置的文档/模型服务提取制造要求、整件工艺和小时/件估时，保留证据、假设和人工复核。
- 新组织首次打开报价规则时，只从当前组织已启用且有权限访问的正式工艺档案初始化自制及委外工序。初始材料清单为空。授权人员在「报价规则」中维护材料、密度、采购单价、工序费率和参考工时。已有组织的材料规则和历史报价快照继续使用原记录。
- 工序规则必须绑定真实 `process_id`，名称与加工类别取自档案；管理端取消通用规则新增、清空绑定及关键词计价入口。服务端拒绝未绑定规则，AI 仅选择绑定的正式工艺编号，核价只按该工艺取价，不按名称、类别或旧规则编号兜底。材料规则和历史报价快照保留。
- 已有环境升级前须备份并显式清理未绑定工艺的工序及外协规则；不自动删除其他租户的配置。
- 个别加工要求无法覆盖时不终止整件规划：`analysis.ai.uncovered_requirements` 逐项保留缺失内容及原因，`planning_status=partial`；已匹配正式工艺的工序仍保存、估时、补齐参数，也可单独采用。按报价人员先看价格、再人工修改的流程，未覆盖要求不阻断核价：先按已有材料及工序生成价格，快照标记 `is_reference=true` 并保存待核对项，页面及导出显示“参考报价”和未自动计入的要求。工时或费率等实际核算参数缺失仍按原机制提示补充，不虚构成本。模型优先按现有工艺的加工能力拆解，钻孔、攻丝等可归入适用加工中心工艺，不因档案没有同名条目就认定缺失；也不使用不适用的工艺凑数。
- Decimal 确定性核价、不含税报价快照、当前登录身份审核、Excel/PDF 导出、零件软删除及恢复。

加工询价用于工程核价。销售报价、客户订单及生产下达在各自的业务页面办理。

### 报价工作台交互

- 核心入口为“上传并生成报价”：提交文件、数量和可选名称后，直接衔接已有后台解析、规则补齐和自动核价。资料不足时显示待补充项，人工完善后重新核价；任务提交失败保留已上传零件，并提示从“生成报价”重试。
- 解析失败或工艺未生成时，报价区优先显示解析提示，可打开“识别依据”查看识别和工艺生成状态；空工序不显示已估算工时的成功文案。已有服务失败提示保留可排查的中文类别，不透传原始响应。
- 左侧询价任务默认收起，页头“任务列表 / 收起任务”控制展开；收起后空间交还图纸与报价编辑区。
- 工作台移除“报价参数”区、追加流程模板和手动新增工序入口。自动生成的工序仍可修改和删除，保留材料参考价、毛坯与费用的人工完善，以及重新解析后的工艺采用。
- 报价流程模板已从前后端移除：不再提供模板配置、追加参数、规则读写或模板明细模型，工序由图纸解析生成；保留工序参数、外协参数、材料价格及毛坯规则。生产管理的工艺路线独立保留。
- 上传、重新生成与选材不再重复展示联网授权提示。页面提示只说明业务进度、结果及下一步操作；服务密钥、环境变量、解析提供商与底层错误不在报价工作台直接展示。服务端原有权限、发送范围和 `cloud_allowed` 校验保留。
- 报价结果位于右侧顶部，优先显示不含税单价及数量合计；费用构成默认收起，“查看和修改报价明细”默认展开，切换零件时也展开。材料与费用单独成页，选材失败或有核价缺项时可从顶部进入完善页。
- AI 选材成功后，材料下拉框直接选中对应的有效规则，支持手动改选；不再只把名称放在提示或占位符里。仍按来源区分 AI 选择和人工固定绑定，材料、毛坯或规则变化后旧 AI 选择失效。材料牌号、模型净尺寸和长方体毛坯均归入“材料与费用”，制造要求页保留处理要求、公差和技术备注。
- 加工与外协按工序摘要卡片展示名称、计价方式、费率及本次核价金额，展开后编辑；外协不再展示加工类别和工时字段，计费单位、重量依据及单件最低收费均有明确标签。估时/计价依据保留在展开内容中。
- 修改后统一点击“更新报价”保存并调用服务端核价；编辑中保留上次总价并明确提示未更新，工序金额显示待更新，不在前端重算正式报价。历史快照及审核/导出约束继续保留。
- “材料与费用”增加“重量预估”，显示单件/整批预计净重和毛坯重量。复用当前选材/人工填写的密度，采用 `重量 kg = 体积 mm³ × 密度 g/cm³ ÷ 1,000,000`；不额外调用模型猜测重量或材料密度。STEP 净体积优先；仅有模型外接尺寸时按实心长方体计算，标为“外形估重（未扣孔槽）”，不冒充零件净重。只有毛坯尺寸时只提供毛坯重量，缺密度则提示补充。
- 零件详情的 `weight_estimate` 独立于报价费用是否齐全，`method_key` 为 `cad_volume` / `model_bounds` / `unavailable`；重量和密度以十进制字符串返回，重量单位 kg，保留 6 位小数。修改密度、毛坯或数量后提示更新；重量由服务端按保存后的参数重新计算。新报价将重量及依据固化在 `result_snapshot.weight_estimate`，报价摘要和导出沿用该快照，不回写历史；不增加数据库表字段、迁移或检索索引。
- 询价单的业务录入与 Excel 模板仅收集客户需求。工程人员确认采用 AI 报价时，系统从该报价快照带入单件预计净重，工程人员可继续调整。缺少可用净重时保留明细原值。旧版 Excel 可继续导入，重量列会被跳过。

## 实现位置与契约

后端位于 `plugins/mes/backend/app/modules/mes/cnc/`；前端位于 `plugins/mes/web/src/views/mes/quoting/`。接口统一 `/api/mes/cnc`，使用 `{code,message,data}`。通过 MES 原有清单、目录、租户任务和源码包机制接入，L1 不增加制造依赖。

`models.py` 定义表，`schemas.py` 校验输入，`repository.py`/`file_repository.py` 负责 SQL 与持久化，`service.py` 编排业务事务，`api.py` 负责参数和动作鉴权。`analysis.py` 在独立子进程计算 PDF/CAD；`ai.py`/`ocr.py`/`drafts.py` 保留云解析及工艺依据；`rules.py`/`pricing.py`/`material_matching.py` 保留规则和核价算法。产物、导出、日志分别由 `artifacts.py`/`exports.py`/`observability.py` 处理。

权限分为 `mes:quote:list`、`mes:quote:manage`、`mes:quote:analyze`、`mes:quote:approve`、`mes:quote:rules`。租户启停、动作权限及组织/本人/关联数据范围由服务端检查，下载沿父零件权限；未配置关联提供器时拒绝放行。规则按零件所属组织选用，不使用其他组织的默认价格。

上传复用 L1 文件场景、绑定与读取服务，校验文件头和 SHA256。预览/下载使用管理端现有会话刷新，令牌不放入 URL。原件由 L1 管理；解析副本及历史产物默认位于 `plugins/core/backend/storage/mes-cnc/<当前租户>/<零件>/<任务>/`，重解析不覆盖旧任务目录。

三维组件按需通过鉴权接口读取当前任务的网格，不依赖页面预取的 Blob 地址；重新解析后按任务标识更新预览。网格读取失败时显示明确提示，并可“重新加载预览”，无需为重新读取已有网格再次调用解析服务。

二维组件直接读取解析时生成的当前页预览图，保留页码切换、缩放与相对坐标标注；不再在浏览器重复下载原 PDF、启动 PDF.js 和重新渲染。原 PDF 仍可单独下载。识别依据中的局部图、OCR 图片和文字稿在打开该页签时按当前页加载，不阻塞图纸及核价表单。

## 当前 询价模型

业务表属于当前租户 schema，不含 `tenant_id`、不写死 schema；使用公共 UUIDv7/组织/审计字段工厂、中文注释、显式外键及删除行为。实际字段以 ORM 为准。

| 表 | 一行代表什么 | 关系和口径 |
| --- | --- | --- |
| `mes_cnc_part` | 一个询价零件及当前制造要求 | 组织、审计、`version_no`、成对软删除；材料、尺寸和金额输入为独立列 |
| `mes_cnc_operation` | 零件的一道当前工序 | `part_id`、可空 `source_job_id`；工时和费率为数值列 |
| `mes_cnc_drawing_file` | 一份绑定的图纸/模型 | `part_id`、`attachment_id → file_attachment`；同零件同类型唯一 |
| `mes_cnc_analysis_job` | 一次明确请求的解析任务 | 父零件、申请人认证身份和租户动作人；同零件仅一个活动任务 |
| `mes_cnc_quote` | 一次核价的历史快照 | 父零件及依据版本；单价/总价 `numeric(18,2)`；审核人引用 `sys_user`，名称按当时快照保存 |
| `mes_cnc_rule_set` | 一个组织的规则控制参数 | 每组织唯一；版本、材料/工序自动补齐开关；历史毛坯余量字段仅保留兼容 |
| `mes_cnc_rule_entry` | 一条材料/工序/外协定义 | `rule_set_id`；可配置编号 `rule_no` 组内唯一 |

报价流程模板已退役；接口不再接受 `config.templates` 或 `template_no`。规则读写仅处理材料、工序、外协三类，跳过旧模板数据，避免尚存的明细外键阻止普通规则保存。旧表不会由自动差异删除，须在目标租户备份后显式创建、审核并执行本地清理迁移。

毛坯采用固定规则：每个模型净尺寸先加 5 mm，再向上取到 5 mm 的整数倍，即 `ceil((净尺寸 + 5) / 5) × 5`。例如净尺寸 24 × 90 × 41.5 mm 对应毛坯 30 × 95 × 50 mm。解析完成后自动补齐空白尺寸，已有人工尺寸保留；材料/工序的自动补齐开关不影响毛坯。原 `stock_allowance` 字段和接口值保留兼容历史配置，不再参与计算，无新增数据库字段。

“按规则补齐毛坯”通过既有 `apply-rules` 接口的 `is_stock_only=true` 只补毛坯，不顺带补材料价格或工序费率。更改尺寸后需要重新人工确认并核价，历史报价快照不回写。已有解析结果可直接补齐，不需要重跑云端解析。

材料改为 AI 选材：`material_ai.py` 将材料牌号、硬度/状态、固定规则补齐后的毛坯尺寸，以及当前组织已启用材料规则的编号、名称、别名、形态、规格区间、计价单位和采购条件交给已配置模型；不发送密度、单价、来源文件或人工备注。

1. 已手选的有效规则优先，AI 不覆盖手选绑定。自动选材不再按字符串匹配或列表顺序取第一条，而由 AI 解释牌号对应、状态、板/棒/型材及采购条件，返回库内规则编号和中文理由；不能确定时返回 `uncertain`，没有适用条目时返回 `unmatched`。
2. 服务端校验结构、已启用编号及板材厚度范围；价格、密度和计价单位从选中规则读取，模型不能生成这些数值。自动补齐只写空白，保留已有数值；来源记录模型、理由、规则及版本，不写成用户手选绑定。
3. 解析任务在材料/工序自动补齐开启、没有手选绑定且密度或单价为空时自动选材。已有记录可在“材料与计价条件”点击“AI 选材”直接单独执行，无需重跑 OCR 或图纸解析；只补材料和空白毛坯，不改变工艺与费率。
4. 选材依据和结果保存在 `analysis.material_selection`；牌号、硬度、毛坯或规则版本变化后旧选择不可再取价，页面提示重新选材。单独选材在模型调用前后关闭/重开事务并核对输入及规则版本；失败不回写，页面显示可重试或手选的错误。解析任务内选材失败会保留图纸结果、显示原因，不自动重发请求。

5083 选材纠偏：供应商 [HABA 牌号资料](https://www.haba.ch/fileadmin/user_upload/Produktblaetter_engl/Alu_28_EN.pdf) 将 `3.3547 / AlMg4.5Mn / EN AW-AlMg4.5Mn0.7` 对应至 `EN AW-5083`，因此可以考虑库内 AL5083，无须规则别名逐字包含全部写法。未明确板/棒时优先考虑同牌号、无附加采购限制的通用参考规则，不主动选进口专用项；图纸和通用规则均未限定交货状态时，不把该空白作为报价参考的阻断条件。明确的状态、形态和采购要求仍须满足，无法区分且无通用条目时继续返回 uncertain。

规格区间的空边界代表不限制：`size_min=8 / size_max=null` 表示 8 mm 及以上，25 mm 符合该厚度范围；不能将没有上限解释为无法判断。价格和密度仍取当前组织已配置的规则，不采用资料中的物性替换客户配置。

密度和单价使用所选材料规则的配置。需要重新取值时先清空现有密度或单价，已手动绑定材料的记录先清除绑定。

工序为关系明细。规则的匹配词、来源、单位和参数由各自 Pydantic 模型校验，属于结构明确的配置定义。报价 `inputs_snapshot`/`result_snapshot` 是当时完整输入和计算依据，不冒充当前业务明细。`analysis` 保存解析证据文档，其页/区域/外部任务标签不是内部 UUID。规则业务编号的历史引用按参数来源快照解释。

业务字典在 MES `dictionary_specs.py` 注册；文件场景和业务访问使用 L1 现有注册契约。

## 后台解析和 AI 边界

`worker.py` 由 MES 的 `PeriodicJob` 按当前已启用租户轮询，每轮领取一个持久化任务，不增加 RQ 或独立业务数据库。行锁分领任务；超出执行租约的任务标记中断，须用户手动重试，不自动重复提交云请求。执行前及写回前通过认证 Service 重建申请人权限。

本地 PDF/STEP 解析沿用当前后端的 Python 解释器，以公共配置 `BASE_DIR`（当前为 `plugins/core/backend/`）作为子进程工作目录，不依赖插件目录层数或启动终端位置。迁移目录后若日志出现 `WinError 267`，更新插件代码并重启后端；失败任务由用户手动重新解析，不自动调用云服务重试。

重解析保留已有工序和人工参数；解析期间输入修改时不自动填表，建议留待复核采用。依据变更递增版本，使当前报价需要重新核算；历史快照不改写。审核先锁零件，检查最新快照、版本、无活动解析和人工确认；审核人来自当前登录身份。

只有用户确认的本次图纸/几何、必要工序定义及上述选材字段发送给配置的服务；单独选材须 `mes:quote:list/manage/analyze` 权限和 `cloud_allowed=true`。不附带 ERP 人员资料、其他组织规则、其他业务记录或人工自由备注。Harness 数据访问按已审查的权限与字段白名单配置。

## 依赖、配置与开通

后端使用 ERP 的 `plugins/core/backend/.venv`。底座依赖安装完成后，在仓库根目录安装 MES 依赖：

```powershell
& './plugins/core/backend/.venv/Scripts/python.exe' -m pip install -r plugins/mes/requirements.txt -c plugins/core/backend/requirements.txt
```

清单同时安装报价和排程所用的 Python 库。仅补装报价依赖时可将 `-r` 改为 `plugins/mes/docs/cnc-requirements.txt`。uv 环境的安装方式见 [MES 插件说明](../README.md#安装后端依赖)。

前端在 `plugins/core/web/` 运行 `pnpm install --frozen-lockfile`，安装 PDF.js、Three.js、marked、DOMPurify 及对应类型。宿主 Vite 已统一将插件源码的 npm 导入解析到管理端依赖；更新配置后重启 `pnpm dev`，无需创建根 `node_modules` 联接。见[插件依赖规则](../../core/docs/plugin-source-layout.md)。

模型和 OCR 凭据配置在宿主的 `plugins/core/backend/config/plugin/mes.env`：

```dotenv
MES_CNC_AI_API_KEY=<模型密钥>
MES_CNC_AI_BASE_URL=https://api.deepseek.com
MES_CNC_AI_MODEL=deepseek-flash
MES_CNC_PADDLEOCR_ACCESS_TOKEN=<文档解析凭据>
```

未填写专用模型密钥时使用现有 `LLM_GATEWAY_DEEPSEEK_API_KEY`。页面在主按钮下直接列出缺少的模型密钥或 PDF 文档解析凭据，并提供管理员配置说明及“重新检查”；修改配置后需重启后端。没有云凭据仍可人工编辑、核价、导出。

管理端只保留“解析并生成初稿”入口，提交后提示任务已进入后台。本地 PDF/CAD 解析仍是处理链路的内部步骤，接口保留 `mode=local`，但不再提供容易与工艺生成混淆的“仅本地解析”按钮。

核对目标库与租户后执行：

```powershell
python scripts/erp.py db revision --plugin mes --schema t_actual
# 审核新表、外键、索引和中文注释，再执行：
python scripts/erp.py db upgrade --plugin mes --schema t_actual
```

将 `t_actual` 换成实际租户。保留既有基线，不重建库、不 stamp。重启后端及管理端，在“应用管理”启用或升级 MES，然后分配菜单与动作权限。组织首次使用时初始化默认规则，后续不覆盖保存过的价格和开关，无需加载演示数据。

模型/接口目录更新使用 [Harness 同步流程](../../core/docs/harness-sync.md)，索引涉及模型调用，需确认目标后独立执行；自由文本、图纸正文和审核姓名不自动加入白名单。

部署验收可使用自制的 PDF 与 STEP 测试件，核对解析、材料匹配、人工修订、权限与导出的完整流程。
