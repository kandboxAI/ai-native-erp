# 资产登记的物料资格与默认配置

2026-11-12：新收货已接入[库存与资产闭环](inventory-asset-lifecycle.md)。所有纳入资产管理的实物统一逐件编号，桌椅等家具也不再新增数量资产；批次号只用于收货追溯。物料表单取消登记方式选择，新模板取消建议方式列。旧字段和数量台账仅保留历史兼容，不自动拆分或清除。仓库责任部门按默认值带出且允许本次调整。以下首次接入升级记录不代表目标库已执行迁移。

## 业务规则

物资档案仍由 inv 的 `md_item` 统一维护，食材、耗材与设备不拆成重复主数据。物料新增以下字段：

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `is_asset_managed` | 是否纳入实物资产管理，不等同于财务固定资产认定 | `false` |
| `default_asset_type_code` | 默认资产类型，引用现有字典 `asset_type` | 空 |
| `default_asset_management_mode_code` | 历史兼容字段；字典 `asset_management_mode`；新资产固定逐件编号，旧 `batch` 值不再控制收货 | 新建或显式资产配置时规范化；普通字段/仓库关系编辑保留历史值 |

是否纳入资产管理由物资档案的已有维护权限控制。分类与名称不作为资产资格判据；不在 inv 中引用食堂或其他教育模型来排除物料。新收货固定生成逐件登记快照；已存的历史方式与来源快照不覆盖。

仅调整物料适用仓库等普通字段时，保留历史登记方式。新建物料或明确编辑资产登记方式时，按逐件编号规则校验。

只有未删除、启用且纳入资产管理的物料可以新建逐件编号资产或确认待登记资产。新增数量资产接口被拒绝，历史记录可继续查询、减少和流转。后端在业务事务内重新校验，并以物料共享行锁防止检查与登记之间发生配置变更。资产登记不会修改物料档案。

物料后来关闭资产管理，不删除或隐去历史资产，不影响已登记资产的调拨、交接及历史查看。资产台账增加“物料资产配置”列及“未纳入，待核对”筛选。该清单表示需要核对配置，并不直接认定记录错误；待确认记录必须先修正物料配置再确认，误登记记录走已有作废流程。

## 查询和界面

- 资产台账点击“新增资产”直接打开独立简洁表单，仓库可不选；选仓库时同步记账，未选时部门、保管人和实际位置必填。不再提供“按数量登记 / 单件登记”手工新增入口；物料候选由服务端按 `is_asset_managed=true` 筛选，统一逐件自动编号；批次号不参与登记方式判断。已有记录的编辑继续保留。详见[库存与资产闭环](inventory-asset-lifecycle.md)。
- 物资档案保留资产开关、默认类型、列表标识和筛选，移除登记方式选择。新建物料默认为不纳入。
- 物料表单沿用“允许登记为资产”及 `is_asset_managed` 字段，提示开启后新收货同步登记并确认；旧 Excel 模板可识别，但按数量登记不再作为可用选项。
- 新增表单使用库存物料候选并在服务端筛选资产资格；已有资产编辑继续用 `AssetItemSelect` 只读回显物料。资产类型来自物料配置，不再提示可选择数量登记。
- 选择资产位置时，默认管理部门与现场负责人须匹配当前返回的可选项后才能带出。匹配不到则留空并提示重新选择及核对位置默认设置，避免下拉框直接显示 UUID；不推断其一定已删除，也不自动修改位置或部门档案。
- `GET /api/asset/item-options` 接收 `org_id`、`keyword`、`page`、`page_size`（最大 100）；先筛选资格，再查询总数和分页，不再截取全量物料前 500 条。
- 接口要求 `asset_register:list`，验证目标组织的数据范围；只读取当前租户共享物料的编号、名称、规格、单位、分类和两个资产默认配置。组织不改变共享物料归属，租户由认证上下文确定。类别软删除后不显示类别名称。
- 原 `/api/asset/options` 的 `items` 也过滤资产资格，仅提供首批 50 项供旧调用方兼容；新登记选择器使用分页接口。位置、部门、人员仍走原有范围验证。
- 台账查询新增 `is_asset_managed` 筛选，与原有组织、责任人、权限范围取交集。

## Excel 兼容

新物料模板为 14 列，保留“纳入资产管理”“默认资产类型”，取消“建议登记方式”。资产管理开关必填是/否；类型支持中文名称与有效编码，导出显示中文名称。

旧 9 / 12 列更新保留未提供的资产资格和类型；已有资产物料写入时方式固定为 `individual`。旧 15 列仍可识别，建议方式空白或“单件登记”可用，填写“按数量登记”或非法值则整批拒绝。导出、预校验与正式导入遵守同一规则。此处为物料档案 Excel 功能，与已移除的入库 CSV 明细导入分开。

演示种子仅对新建的指定设备/家具物料设置资产类型和逐件方式，不依据名称推断、不覆盖已有物料。原设计字典 `dd_spec.py` 已同步三列与登记方式字典；未重建全量字典或覆盖生成模型。

## 首次接入的历史升级记录

备份并核对目标数据库后执行（`t_actual` 替换为实际租户）：

```powershell
python scripts/erp.py db revision --plugin inv --schema t_actual
# 审核输出文件后执行
python scripts/erp.py db upgrade --plugin inv --schema t_actual
```

审核 `md_item` 新增三列，`is_asset_managed` 非空且服务端默认 `false`；两个默认编码可空。不自动将现有物料设为资产，不修改已发布基线或既有交接记录。

重启后端，在“应用管理”升级相应应用/套件，以现有幂等目录同步机制补齐 `asset_management_mode` 字典；重新构建/启动管理端。升级后先在物资档案核对电脑、空调、桌椅等资产物料并打开开关，食材保持关闭。已有所有物料初始均为未纳入，核对前资产选择器可能为空。

表/接口元数据变化后，使用 Harness 的环境由用户显式执行 `python scripts/erp.py ai sync --schema t_actual`；需要重建索引时在完成模型配置后加 `--index`。


人工验收：

1. 电脑和桌椅开启资产管理并设置资产类型；南瓜等普通物料保持关闭。
2. 点击新增资产直接打开简洁表单，候选可搜到电脑和桌椅、搜不到南瓜；CSV 导入入口及旧接口已移除。
3. 同批次入库 10 台电脑产生 10 个不同编号；不填写批次号入库 20 把椅子产生 20 个不同编号；资产小数数量被拒绝。
4. 领用后退库沿用原实物，不再增加资产卡片；中途登记失败时库存与资产一并回滚。
5. 导出物料、修改资产开关、预校验并回导；使用旧 12 列模板更新其他字段不应清空资产配置。
6. 历史资产仍在台账中，“未纳入，待核对”能列出待检查记录；已确认资产的交接流程保持可用。
