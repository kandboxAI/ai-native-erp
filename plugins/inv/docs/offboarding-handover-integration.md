# 来源业务资产交接

业务来源单据通过公开 Service 创建、核对、提交和撤回资产交接单。非空来源 ID 的交接不能从资产页独立提交和撤回；人工发起的资产交接继续使用原流程。来源模块注册授权摘要、来源锁及完成回调，inv 不导入 EDU。

有效来源增加部分唯一索引，升级前须核对同一来源、同一组织的重复有效单据。保存草稿保留明细 ID，避免破坏历史业务关联；来源资产清单由来源业务核对，资产页可维护去向、接收与拒收重办。

EDU 联动的主设计及升级步骤见仓库的 离职交接与资产交接闭环。

同一来源允许按资产所属组织分单。公开 `source_records` / `source_details` 返回全部有效分单；单组织创建按来源及 `org_id` 查找，保持核对幂等。EDU 决定学校/校区范围并逐组织鉴权，inv 不引入学校组织语义。来源模块须在同一事务先锁来源、按组织/主键顺序锁分单，再统一提交或撤回。

升级时将旧 `uk_asset_handover_source_type_code_source_id` 替换为 `uk_asset_handover_source_type_code_source_id_org_id`，部分唯一键为 `(source_type_code, source_id, org_id)`，条件仍为来源非空且状态非作废。保留历史数据，不修改已发布基线；由维护者按目标环境生成审核迁移。新增组织展示字段 `org_name` 由来源详情查询返回。

## 未接收人工交接单作废

资产交接详情提供“作废交接单”，要求 `asset_handover:manage` 及该单据组织数据范围，不按管理员角色名放行。仅来源为人工发起、无来源 ID，且状态为草稿或待接收的单据可作废；任何明细已接收、存在确认人/确认时间，或整单已完成时拒绝。离职流程生成的单据不能直接作废，以免来源流程与资产清单脱节。

接口 `POST /api/asset-handovers/{handover_id}/void` 接收 `expected_version` 和必填 `reason`（去除首尾空白后 1–1000 字）。操作先按既有顺序加锁，重新检查权限、状态和版本，防止接收及作废并发。将头状态置为 `voided`，记录现有 `voided_at`、`voided_by`、`void_reason`，更新审计和版本。保留原明细、提交记录、拒收记录，不删除资产、不改变保管关系、不触发接收或来源完成回调。

占用查询只包含草稿及待接收交接单，因此作废后资产可重新纳入离职交接；单纯撤回到草稿不会释放占用。作废详情展示原因和时间，明细标为已作废，停止接收。确认弹窗展示具体单号及影响，取消不提交，服务端拒绝时刷新详情。已有接收的单据不提供此入口。

本功能复用现有模型字段和作废字典状态，无新增数据库迁移；既有跨组织索引升级要求仍保留。接口快照按 Harness 同步流程显式更新。

离职来源生成及更换接任人支持由 EDU 传入已鉴权 `source_org_ids`，允许责任部门属于该集合中的其他组织；资产单头及资产本身仍属于原组织。该参数不通过 HTTP 接收，未传时仅允许本组织，空范围拒绝。部门必须有效且未删除，选择顺序为同组织接任部门、范围内原部门、范围内接任部门；失败提示具体资产。无模型变更和新增迁移。

核对性能：现有明细仅查询资产 ID；无新增资产时保留原版本并跳过明细写入；同批新增明细复用事务内只读档案查询，但资产状态及未完成交接占用仍实时检查。缓存不跨请求，不修改权限和事务规则。
