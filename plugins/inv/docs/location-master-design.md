# 位置信息统一维护

## 使用方式与代码归属

在现有管理端增加一个「位置信息」菜单，以普通列表集中维护全校的位置名称、类型、组织归属、必填经纬度、坐标系和启停状态。资产、仓库及两类巡查在填写位置时共用位置选择器。

位置是现有 inv 内部的共享模块，代码位于 `plugins/inv/backend/app/modules/location/`，稳定导入名为 `app.modules.location`，数据表为 `md_location`。页面、API 和选择组件随 inv 一起交付，沿用现有 inv 数据库维护流程。EDU 继续通过已有 inv 依赖访问位置能力；应用管理不增加位置插件，不新增独立版本、开通步骤或迁移分支。

菜单统一为「系统管理 → 位置信息」，inv 独立部署和教育组合使用同一个公共维护入口。EDU 侧栏布局同步放在系统管理，不在后勤管理重复展示；已有后勤/库存挂载显式启用历史默认父级展示兼容，授权导航下发时放到系统管理，不依赖目录同步；保留数据库菜单原值、ID、路径及授权，自定义挂载不覆盖。位置权限仍归入已有 inventory 模块，查询为 `md_location:list`，维护为 `md_location:manage`。

## 位置与坐标规则

- `org_id` 是数据归属；当前位置按名称独立维护，不建立上下级。列表、搜索和业务选项只使用位置名称，建议用“一号教学楼301室”等完整名称区分位置。原 `parent_id` 列及历史值暂存兼容，不对外提供层级，也不参与启停、引用或删除校验；请求仅接受该旧字段为空值，新建不建立关系，编辑保留历史存储值。
- 每个位置都必须有经纬度，类型为 `numeric(10,7)`，纬度范围 [-90,90]，经度范围 [-180,180]。不自动用 0 或父级坐标填补缺失值。
- 相同坐标可对应不同楼层或房间，通过位置名称区分，经纬度不负责识别楼层。
- 坐标系通过 `md_coordinate_system` 字典明确记录。管理弹窗隐藏坐标系选择，统一录入高德/微信 GCJ-02 坐标，移除浏览器 WGS84 定位入口。已有其他坐标系记录不自动改标；编辑时须重新选点，或清空后重新填写两项高德经纬度。现有手机巡查仅选择 GCJ-02 位置。
- 位置编号由服务端自动生成（`LOC-` 加位置 UUID 的大写十六进制），弹窗无需填写。保留旧编号，编辑不得改号；创建接口兼容旧客户端传入编号。编号在组织内有效记录中唯一，类型来自 `md_location_type` 字典。位置更新检查版本号，校验所属组织与有效字典。
- 新增时优先采用组织筛选，再采用账号默认组织。默认组织须在当前维护权限允许的有效组织中；没有账号默认组织且只有一个可选组织时自动选取，否则由用户选择，不默认取列表第一项。多组织账号新增时可切换授权组织。编辑时，拥有 `md_location:manage` 且该权限数据范围为 `all` 的管理员可修改所属组织；不按管理员角色名放行。服务端 `/api/location/meta` 返回 `can_change_org` 控制选择器，保存仍重新鉴权。仅允许调整未被业务引用的位置；通过现有消费者契约检查仓库、资产配置及巡查（含历史引用），有引用时拒绝直接修改归属，并提示先处理关联。调整同时按固定顺序锁定原组织与目标组织，重新校验原记录权限、版本、目标组织启用状态及目标组织内编号唯一性；保留位置 ID、编号、坐标和创建审计，递增版本并更新修改审计。编辑请求省略组织时保留原归属。
- 停用位置保留历史引用，但自身及后代不能用于新业务。已有下级或业务引用时禁止删除，应使用停用。

管理界面为普通列表，按位置名称搜索、按组织/状态筛选。布局遵循 PC 列表规范：透明页头及统一智能助手入口，筛选与列表合并卡；新增操作位于筛选下方，右侧保留列设置，分页使用公共组件。位置仅显示名称，不再展示编号、路径或位置树；新增/编辑移除上级位置。地图选点复用现有高德拾取链接，支持复制、粘贴和手工录入，不需要额外配置地图 SDK 密钥。

## 业务接入与历史数据

### 资产

2026-11-12 功能收敛：已移除旧资产地点补关联抽屉及 `/api/asset/locations` 旧维护路由。新资产直接选择统一位置并自动建立内部配置；旧位置和历史引用不自动修改。下方旧升级记录仅用于理解已有结构，不表示仍有人工补关联入口。

复用现有资产位置逻辑，保留原 `asset_location` UUID，以及台账、交接单和变更事件的引用。新增 `physical_location_id -> md_location.id`；多个历史资产地点可以关联同一个统一位置；内部资产地点只承担旧外键兼容。

位置名称、类型和坐标由公共位置维护，编号由系统维护。原独立资产位置菜单和旧地点补关联入口均已移除，不再通过资产 HTTP 接口新增、补关联或改绑地点。

新资产直接选择尚无资产配置的统一位置，首次登记时按需建立内部配置。已有资产地点与引用保留，位置更新仍在同一事务同步名称和类型投影；资产移动通过调拨或交接办理，不根据旧默认责任信息修改资产。

资产责任信息由资产本身维护：管理端统一使用「责任部门」（登记必填）和「资产保管人」（可选），提示为“请选择责任部门/资产保管人”。切换资产位置不填写、清空或覆盖已选责任信息，单纯移动位置保留原资产责任；变更责任仍通过相应业务动作显式提交。单件和批量登记均由服务端校验责任部门，未传保管人按空值处理，不读取位置默认值。资产位置选择选项不再发布默认部门/保管人，资产位置写入请求不再接受这两项字段。旧 `asset_location.default_department_id/default_custodian_user_id` 列及值保留，不作为当前默认行为依据；在位置关联升级中同步历史字段说明，不清除旧值。

### 仓库

`inv_warehouse.location_id` 引用统一位置，新建仓库必选。原 `location` 文本保留为补充说明，仓库编号、库存和申领范围继续属于仓库。仓库列表返回位置名称及坐标。历史仓库的新关联列可空，待人工关联；不凭旧文字猜测坐标。

### 巡查

`fac_patrol_point.location_id` 引用统一位置，新增或编辑必须选择位置。原「巡查地点/巡查配置」独立菜单 `LogisticsPatrolPoints` 退役，后勤巡查仅保留巡查记录入口；半径等规则收进记录页的「巡查设置」抽屉，学生科同样取消独立配置页签。既有业务权限、点位 ID 和历史数据保留。表单只选择统一位置并维护半径、排序和启停，业务归属由后勤/学生科入口确定。名称、说明及坐标由服务端读取统一位置，旧客户端传入名称/说明兼容接收但不采信；旧点位同名字段仅作兼容投影。小程序直接读取打卡权限和数据范围内启用、使用 GCJ-02 的统一位置，无需管理员预先添加巡查配置；未配置时默认半径 200 米，已有专属半径覆盖默认值，明确停用或移除的巡查位置不自动恢复。未关联的旧巡查点不会按同名自动合并；统一位置停用或坐标系不匹配时不允许新打卡。

新打卡记录保存当时的位置 ID、统一位置名称、目标经纬度及半径快照，供后续追溯。历史记录的新列保留为空，不补造当时的坐标或判断依据。旧巡查地点的经纬度经人工核对组织、真实地点和坐标系后可以复用。

## 接口与权限边界

管理接口为 `/api/location/list`、`/meta` 和位置新增、修改、删除接口，随 inv 路由注册。修改、删除携带 `expected_version`。

公共选择接口为 `/api/location/options?permission_key=...&org_id=...`，只接受接入模块声明的权限白名单，校验用户真实拥有的权限及对应数据范围。业务选择位置无需额外取得维护权限，选项仅返回位置标识、名称和坐标等必要元数据，不返回内部备注或审计信息。旧响应 `path_name` 兼容为位置名称、`parent_id` 固定为空，查询过大时明确要求按组织筛选，不静默截断。

仓库编辑按仓库所属组织和 `inventory_warehouse:update` 权限范围加载位置。选择器区分加载中、接口失败和成功空列表；加载失败可重试，成功空列表提示核对组织、启停及权限范围。原位置不在候选中时保留原名称及关联，不在加载时提前判为失效，不自动清除或放宽组织范围。

巡查按名称检索通过位置模块公开的名称匹配契约，关联同时匹配位置 ID、组织及存活状态；业务查询仍承担自身权限、范围与软删除过滤。跨模块关联调用公开位置校验能力，仅校验所选位置自身的组织、启停和存活状态；写操作使用租户及组织级事务锁。引用检查及资产兼容投影由数据所有者提供处理器，位置模块不反向依赖 EDU。历史业务引用继续阻止位置删除，未安装业务表时跳过该模块的检查。

## 位置模块原升级记录

本次仅修改源码、模型及声明，未访问业务库、生成或执行迁移、加载种子、调用外部模型或构建索引。

在备份并核对目标连接后，由维护人员在仓库根目录生成本环境差异：

```powershell
& '.\backend\.venv\Scripts\python.exe' scripts/erp.py db revision --plugin edu --schema t_actual
```

`t_actual` 替换为实际租户。仅物资与库存部署使用 `--plugin inv`。新增位置表和资产/仓库关联归入 inv，巡查关联和历史快照归入 edu；不改写已发布基线。

审核新增表、外键、部分唯一索引和快照列。已有业务表的关联列须可空，保留旧数据；禁止删除旧资产位置、重建业务记录或批量补造坐标。审核后执行：

```powershell
& '.\backend\.venv\Scripts\python.exe' scripts/erp.py db upgrade --plugin edu --schema t_actual
& '.\backend\.venv\Scripts\python.exe' scripts/erp.py dev sync --plugin edu --schema t_actual
```

`dev sync` 仅用于开发环境；其他环境通过已有 inv/EDU 更新流程同步目录。重启前后端、刷新授权菜单，为维护人员分配位置查询/维护权限。无需安装或启用额外的位置应用。

录入真实位置和坐标；新资产直接选择统一位置，仓库及巡查地点沿用各自配置流程。恢复实际巡查前须完成对应点位关联。用管理员及受限账号验证坐标必填、位置选择、位置停用、越权拒绝、资产历史保留和巡查距离。

模型与接口变化后，在目标环境显式同步 Harness 快照；仅在获准调用已配置向量模型后才构建索引：

```powershell
& '.\backend\.venv\Scripts\python.exe' scripts/erp.py ai sync --schema t_actual
# 获准重建索引时追加 --index
```

本次没有新增 AI 资源提供器或扩大字段白名单。坐标、自由文本及业务数据不因此自动开放。

## 字典与验证状态

原混合字典设计源同步位置表、坐标类型及仓库/资产关联；巡查增量以本设计和实际 ORM 为准。旧全量字典生成器仍有四项既有校验错误，生成产物未覆盖，不用旧模型生成器覆盖当前插件源码。

离线测试覆盖坐标必填与边界、组织数据范围、位置停用、历史层级不影响独立选用、并发版本、引用保护、资产旧 ID、巡查当前坐标和历史快照。页面测试使用隔离会话和模拟接口，不能代替目标数据库升级后的业务验收。

位置列表外观调整仅涉及管理端页面及验证，不需要数据库迁移或菜单同步。使用真实公共组件验证菜单自定义标题、智能助手入口、列显隐、操作栏位置、单一分页、空列表与窄屏。全局分页模板审计仍报告考试成绩、教学评价及物资领用三个既有页面使用原生 Pure 表适配，未在位置样式任务中改动这些页面。

当前位置按名称简化的调整不变更数据库模型、不清除历史关系，无需数据库迁移。相关验证覆盖旧父级不限制选项或引用、请求不能新建层级、编辑保留历史 ID/编号/存储关系、平面列表名称搜索和弹窗移除层级。

小程序直接选用补充：选项 GET 不写库；首次有效打卡在同一事务中自动建立内部巡查兼容关联，保留历史点位 ID 和打卡外键。提交支持 `location_id`，兼容旧客户端的 `point_id`（未配置选项可使用统一位置 ID）。服务端重新校验位置权限、组织范围、启停、坐标系和本业务规则，按组织锁串行建立关联，照片绑定或校验失败不提交。读取专属规则严格匹配已授权的位置 ID 与组织，并隔离后勤/学生科；删除标记仅用于阻止已移除的巡查点被默认规则重新启用。旧同名未关联记录不改动，必要时为内部名称缓存附加位置 ID 以满足旧唯一约束，界面和打卡快照始终使用统一位置名称。无数据库结构变更或自动补数据步骤。

责任信息收敛验证覆盖：旧位置带默认值时单件/批量登记仍需手选责任部门、保管人可空、前端切换位置保留手选责任信息、仅移动位置不变更责任、补关联不提交或校验旧默认职责、待关联筛选在计数和分页前按权限范围执行。

### 原多个旧地点关联结构（功能已退役，结构保留）

旧版本曾支持多个旧地点关联到同一真实位置。现已移除补关联写入逻辑，但已有地点 ID、编号、责任字段、原资产/交接外键和关联索引保留，不自动合并资产。选择器按真实位置去重，并携带全部历史地点标识，用于已有表单显示及台账筛选；筛选一个统一位置或其任一旧地点时，返回同组织的全部关联资产，仍执行资产权限和软删除过滤。内部选项与引用解析按启用状态、主关联、创建顺序稳定选择，显式历史 ID 保持原指向。

模型将 `uk_asset_location_physical_location_id` 部分唯一索引替换为普通索引 `idx_asset_location_physical_location_id`。组织内旧地点编号唯一索引仍保留，所以不能把多个旧地点编号都改成统一位置编号。模型及字典设计同步说明；没有生成或执行目标环境迁移。

& '.\backend\.venv\Scripts\python.exe' scripts/erp.py db upgrade --plugin inv --schema t_actual

`t_actual` 替换为实际租户；需要指定库名时附加 `--database <当前库名>`。已完成对应迁移的环境直接部署更新。允许多对一之后，不可直接重新建立旧唯一索引作为无损回退；回退须按备份和实际关联关系单独评估。升级后按 Harness 同步流程显式更新本环境表/接口目录，索引重建需单独授权。
